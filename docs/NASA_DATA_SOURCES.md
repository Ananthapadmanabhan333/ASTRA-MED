# NASA data sources: inventory and scientific limitations

ASTRA-MED's space environment module (phase 4) uses three public NASA sources. Everything in this
file was checked against the providers' own pages and live responses on 2026-11-12. For current
record counts, collection periods and data-quality figures, see the generated
[data source report](reports/nasa-data-sources-report.md) (`python -m app.space.report`).

> ASTRA-MED is an independent research prototype, not affiliated with or endorsed by NASA. Its crew
> are fictional and their physiology is simulated. The NASA data below are real, but none of it is
> any astronaut's personal health or dose record.

## Data categories

Every value the space module serves carries exactly one category, and categories are never summed
or converted into one another.

| Category | Meaning | Examples |
| --- | --- | --- |
| `measured` | An instrument reading published by NASA | ISS cabin temperature; ISS absorbed dose (EDA) |
| `indicator` | An environmental event or index | Solar flare, SEP event, geomagnetic storm (DONKI) |
| `model` | Space-weather model output, not an observation | WSA-ENLIL runs (DONKI) |
| `estimate` | Derived from a published measurement for a hypothetical case | Cruise dose estimate from MSL RAD's 1.84 mSv/day |
| `simulated` | Generated by the ASTRA-MED simulator | Crew vitals, crew dose, solar particle event test scenarios |
| `metadata` | Catalogue records | OSDR study titles, organisms, missions |

Radiation uses four of them, labelled A to D in the dashboard:

- **A. Measured:** EDA dosimetry.
- **B. Indicators:** DONKI events.
- **C. Estimate:** the MSL-based cruise rate.
- **D. Simulated:** the simulator.

A flare or particle event is never turned into a dose. Absorbed dose (mGy) is never added to dose
equivalent (mSv).

## 1. DONKI: Space Weather Database Of Notifications, Knowledge, Information

| | |
| --- | --- |
| Provider | NASA Community Coordinated Modeling Center (CCMC) and the Moon to Mars Space Weather Analysis Office (M2M SWAO) |
| Homepage | https://ccmc.gsfc.nasa.gov/tools/DONKI/ |
| Endpoints, in order | `https://api.nasa.gov/DONKI/{type}` (NASA Open APIs gateway; API key) → `https://ccmc.gsfc.nasa.gov/DONKI/WS/get/{type}` (official CCMC web service; no key) |
| Types used | `FLR` flares, `CME` coronal mass ejections (with CME analyses), `SEP` solar energetic particle events, `GST` geomagnetic storms (Kp series), `RBE` radiation belt enhancements, `IPS` interplanetary shocks, `HSS` high-speed streams, `MPC` magnetopause crossings, `WSAEnlilSimulations`, `notifications` |
| Format | JSON array per request; each type has its own ID field (`flrID`, `activityID`, `sepID`, `gstID`, …) and times as `YYYY-MM-DDTHH:MMZ` (UTC, minute precision) |
| Query | `startDate`, `endDate` (`YYYY-MM-DD`); notifications also `type=all` |
| Update frequency | Event-driven; records are often revised (`versionId`) in the days after an event |
| Units | Flare class (GOES 1–8 Å X-ray: A, B, C, M, X) → peak flux in W/m²; CME speed km/s; Kp 0–9 in thirds |
| Licence and use | NASA open data, provided "as is" without warranty. CCMC asks that event and validation studies be done with the knowledge and collaboration of the submitting forecasters, researchers, model developers and CCMC, and points to its publication policy for acknowledgements |
| Category | `indicator` (events, notifications); `model` (WSA-ENLIL) |

**Endpoint status found during integration (2026-11-12):**

- **The api.nasa.gov DONKI proxy returns HTTP 404 for every type.** Its upstream path ends in a
  trailing slash (`/DONKI-API/get/FLR/`), which the origin rejects. This follows CCMC's
  2026-09-30 migration of DONKI to new official URLs (`kauai.ccmc.gsfc.nasa.gov` →
  `ccmc.gsfc.nasa.gov`; paths after `/DONKI/` unchanged).
- **How ASTRA-MED responds:** it still tries api.nasa.gov first, as the integration brief
  specifies. On the first 404 it opens a circuit breaker for 6 hours and uses the CCMC origin.
  Each stored record notes which endpoint served it.
- **DEMO_KEY limit:** the public key's limit was 10 requests per hour on that day. Set
  `ASTRA_NASA_API_KEY` for a personal key.

**Validation and normalisation:**

- Each record must have its ID and a parseable UTC time. Records that fail are counted as invalid
  and never guessed.
- A record listed twice in a response keeps its highest `versionId`.
- Re-ingesting a stored event updates it only when the version is newer or the content changed;
  otherwise it is counted as a duplicate.
- The original record is stored unchanged in `raw`.

**Severity, only where the record contains the defining quantity:**

- **Flares → NOAA R scale**, from peak X-ray flux: R1 ≥ M1, R2 ≥ M5, R3 ≥ X1, R4 ≥ X10, R5 ≥ X20.
- **Storms → NOAA G scale**, from the maximum Kp. Kp thirds count up, so "n-" counts as n; 9- stays
  G4 because NOAA defines G4 as "Kp = 8, including 9-".
- **CMEs → DONKI/SWPC speed classes:** S < 500, C < 1000, O < 2000, R < 3000, ER ≥ 3000 km/s. This
  is a speed class, not an impact scale.
- **SEP and RBE records carry no flux, so they stay unclassified.** No NOAA S-scale level is
  assigned. SEP detections whose instrument is a model (for example `MODEL: REleASE`) are flagged
  `model_derived`.

**Scientific limitations:**

1. **Research quality.** CCMC states that DONKI's real-time space weather information and
   simulations "should be considered only as prototyping quality and in research context". NOAA's
   Space Weather Prediction Center is the official U.S. Government source for forecasts and
   warnings; DONKI notifications describe themselves as experimental.
2. **Near-Earth vantage.** Events are observed by near-Earth or Sun-pointing assets (GOES, ACE,
   SOHO, SDO, STEREO). A spacecraft in Mars transit sits at a different heliocentric position. An
   Earth-side flare or SEP may not reach it, and the reverse is also possible. ASTRA-MED does not
   model this geometry.
3. **Records can change.** Analyses and links are revised. Recent days are re-synchronised each run
   (a 3-day overlap).
4. **Days without events.** A day with no stored event means "no event reported" only inside a
   successfully queried range. The correlation engine records which ranges were queried and treats
   every other day as unknown.

## 2. Environmental Data App (EDA): ISS cabin telemetry and radiation dosimetry

| | |
| --- | --- |
| Provider | NASA Open Science Data Repository (OSDR), Ames Research Center |
| App | https://visualization.osdr.nasa.gov/eda/ (API reference: `/eda/api_reference`) |
| Endpoints | `https://visualization.osdr.nasa.gov/eda/api/missions/`, `…/missions/{name}/telemetry_data/`, `…/missions/{name}/radiation_data/` |
| Missions | 24 listed on 2026-11-12: Rodent Research (RR-1 … RR-28), APEX-03-1/-2, APEX-04, VEG-01A/B/C |
| Format | JSON arrays. Telemetry: `time`, `temperature_iss/_ground`, `humidity_iss/_ground`, `co2_iss/_ground`, `milestones`, at about 1–5 minute resolution. Radiation: daily `time`, `gcr`, `saa`, `total`, `milestones` |
| Units | Temperature °C; relative humidity %; CO₂ ppm; dose **mGy/day, absorbed dose in water** (from EDA's own chart axes and tooltips) |
| Update frequency | Historical releases per mission; rarely changes. Re-checked weekly |
| Licence and use | OSDR data are distributed under NASA's open access policy (NASA Science Mission Directorate Science Information Policy). OSDR asks for a bibliographic citation of the data used |
| Category | `measured` |

**Validation and quality checks** run on the raw records before aggregation:

- **Plausibility ranges:** temperature 5–45 °C, RH 0–100 %, CO₂ 0–20,000 ppm, dose 0–5 mGy/day per
  component (0–10 total). Values outside are excluded and counted.
- **Split rows:** some missions (seen in RR-7, RR-10, RR-18) list one timestamp in two rows, each
  carrying some of the fields. Rows are merged per timestamp, so a field that is null in one row and
  present in the other is not counted as missing. Extra rows are reported as merged; values that
  disagree are reported as conflicts, and the median is kept.
- **Missing values, gaps and dose consistency:** missing values are counted per timestamp. Gaps
  longer than three times the median sampling interval are counted, and the longest is reported.
  For dosimetry, GCR + SAA is checked against the reported total (tolerance 0.002 mGy).
- **Approximated launch days:** days up to and including the "Transfer to ISS" milestone are
  flagged `approximate`. EDA states the launch-vehicle dose is approximated from US Lab averages,
  because there was no dosimetry on the vehicle.
- **Storage:** telemetry is stored as hourly mean, minimum, maximum and count; dosimetry stays
  daily.

**Data issues found in the live data (2026-11-12):**

- **RR-18 relative humidity reaches 125.8 %**, which is physically impossible. These 1,434 points
  are excluded as out of range.
- **Some sensors are absent for some missions.** For example, RR-18 has no ISS CO₂ series.

**Scientific limitations:**

1. **Historical only.** These are measurements from specific missions between 2014 and 2024. They
   are never presented as current ISS telemetry.
2. **Location dose, not crew dose.** EDA's doses are for the experiment location, interpolated or
   extrapolated from nearby dosimeters in a preliminary analysis by NASA-JSC's Space Radiation
   Analysis Group (SRAG). They do not account for shielding by the sample enclosure. EDA's reference
   page states doses to payloads should be considered accurate to within about 10 %, given known
   variation across ISS modules.
3. **Local sensors.** Telemetry comes from sensors near the rodent hardware, in the ISS cabin and
   in ground-control habitats. It is not a whole-station average.

## 3. OSDR study catalogue

| | |
| --- | --- |
| Provider | NASA Open Science Data Repository, Ames Research Center |
| Repository | https://osdr.nasa.gov/bio/repo/ |
| Endpoint | `https://osdr.nasa.gov/osdr/data/search?term=…&type=cgene&from=0&size=…` (no trailing slash; `/search/` returns 404) |
| Format | Elasticsearch-style JSON: `hits.total`, `hits.hits[]._source` with `Accession`, `Study Title`, `Study Description`, `organism`, `Project Type`, `Flight Program`, `Mission` {`Name`, `Start Date`, `End Date` in US date formats}, `Study Assay Technology Type`, `Study Public Release Date` (epoch seconds), `Project Identifier` |
| Topic presets | radiation, rodent research, spaceflight, cardiovascular (physiology), environmental monitoring; free-text search is also available |
| Update frequency | Studies are released continuously; refreshed daily |
| Licence and use | NASA open access policy; cite each study with the citation in its OSDR record. OSDR's terms add that the U.S. Government assumes no liability for the accuracy, completeness or usefulness of the data |
| Category | `metadata` |

**What is ingested:** only study metadata. No study data files are downloaded. Studies are linked to
EDA missions through mission codes in the project identifier or title (for example `RR-1_BSP` →
RR-1).

**Scientific limitations:**

- Most studies concern cells, plants, microbes or rodents, and many are ground radiation exposures.
- They give research context only, never crew physiology.

| RadLab Portal and Data API (`visualization.osdr.nasa.gov/radlab/`) | Portal returned HTTP 500; the API needs detector-specific query parameters. A good future source for ISS detector time series (DOSTEL, Liulin-5) |

| Other NASA Open APIs (APOD, NeoWs, EONET, EPIC, rover imagery) | Not relevant to radiation, space weather or crew health |
| NASA Life Sciences Data Archive (LSDA) | Crew physiology archives are restricted and need a formal data request |

## Handling the API key

- **Where it lives:** `ASTRA_NASA_API_KEY` is read only by the backend, as a `SecretStr`.
- **Never exposed:** it is never logged, returned by the API, stored in the database, or sent to
  the browser. URLs are redacted before they appear in sync logs or error messages.
- **Tested:** the test suite asserts the key appears in no API response and in no OpenAPI output.
- **Without a key:** if it is unset, NASA's public `DEMO_KEY` is used for api.nasa.gov.
