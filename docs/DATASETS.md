# Dataset inventory and provenance

Every dataset ASTRA-MED uses, generates or cites, with where it comes from, how it is processed
and what it may and may not be used for. Source URLs were checked live on **2026-11-14** (HTTP
status in the last column of the summary table). Record counts come from the generated
[NASA data source report](reports/nasa-data-sources-report.md) of the same day.

> **No endorsement.** ASTRA-MED is an independent student research prototype for the NASA Space
> Apps Challenge 2026. It is not affiliated with, endorsed, certified or sponsored by NASA, the
> Canadian Space Agency or any other agency. NASA data are used under NASA's open-data policies and
> are cited as their providers request. The crew are fictional; **every crew measurement is
> simulated.**

## Real external data

### D1. DONKI: Space Weather Database Of Notifications, Knowledge, Information

| Field | Value |
| --- | --- |
| Organisation | NASA Community Coordinated Modeling Center (CCMC) with the Moon to Mars Space Weather Analysis Office |
| Original URL | https://ccmc.gsfc.nasa.gov/tools/DONKI/ ; web service `https://ccmc.gsfc.nasa.gov/DONKI/WS/get/{type}` ; NASA Open APIs proxy `https://api.nasa.gov/DONKI/{type}` |
| Collection period | DONKI's archive; ASTRA-MED synchronises the last 180 days and then incrementally. Stored on 2026-11-14: 3,296 events from 2014-09-17 to 2026-11-13 and 241 notifications |
| Units | Flare class (GOES 1–8 Å X-ray, A–X) → peak flux W/m²; CME speed km/s; geomagnetic Kp 0–9 in thirds; times UTC, minute precision |
| Licence / terms | NASA open data, provided by CCMC "as is" without warranty; acknowledge per CCMC's publication policy ("Data courtesy of the CCMC DONKI system") |
| Format | JSON arrays per event type (FLR, CME, SEP, GST, RBE, IPS, HSS, MPC, WSAEnlilSimulations, notifications) |
| Processing | Validated (ID and parseable UTC time required; invalid records counted, never guessed); highest `versionId` kept; raw record stored unchanged; severity only where the record carries the defining quantity (flares → NOAA R scale, storms → NOAA G scale, CME speed class); SEP/RBE left unclassified (no flux) |
| Limitations | CCMC labels real-time content prototyping quality for research use; NOAA SWPC is the official U.S. forecast source; near-Earth vantage point (not a Mars-transit spacecraft's); records are revised after the event; an event is never converted into a dose |
| Integration status | **Integrated.** The api.nasa.gov proxy returned HTTP 404 again on 2026-11-14 (first seen 2026-11-12, after CCMC's 2026-09-30 URL migration); a circuit breaker switches to the CCMC origin, and every stored record notes which endpoint served it |
| Where used | Space environment pages, mission timeline, correlation engine, mission-control context for alerts (events within ±48 h), radiation category B |

### D2. OSDR Environmental Data App (EDA)

| Field | Value |
| --- | --- |
| Organisation | NASA Open Science Data Repository (OSDR), Ames Research Center; dosimetry interpolated by NASA-JSC Space Radiation Analysis Group |
| Original URL | https://visualization.osdr.nasa.gov/eda/ ; API `https://visualization.osdr.nasa.gov/eda/api/missions/` and `/missions/{name}/telemetry_data/`, `/radiation_data/` |
| Collection period | Mission-specific, 2014-09-20 (RR-1) to 2024-05-06 (RR-28); 24 missions listed, 17 with data stored (80,226 hourly aggregates) |
| Units | Temperature °C; relative humidity %; CO₂ ppm; dose **mGy/day, absorbed dose in water** (GCR, SAA, total) |
| Licence / terms | NASA open access policy (Science Mission Directorate science information policy); cite the data used |
| Format | JSON arrays; telemetry at ~1–5 min resolution, dosimetry daily |
| Processing | Plausibility ranges (5–45 °C, 0–100 % RH, 0–20,000 ppm CO₂, dose 0–5 mGy/day per component); split rows merged per timestamp with conflicts reported; gap detection; GCR + SAA = total check (±0.002 mGy); launch days flagged approximate; telemetry stored as hourly mean/min/max/count |
| Limitations | Historical only, never shown as current ISS conditions; location dose at the experiment, not crew dose (±~10 % across modules per EDA); local sensors near rodent hardware; RR-18 humidity reaches an impossible 125.8 % (1,434 points excluded) |
| Integration status | **Integrated** (category A "measured" in the radiation view; ISS environment page) |

### D4. MSL Radiation Assessment Detector, cruise dose rate

| Field | Value |
| --- | --- |
| Organisation | NASA/JPL Mars Science Laboratory mission; published by Zeitlin et al. |
| Original source | C. Zeitlin et al., "Measurements of energetic particle radiation in transit to Mars on the Mars Science Laboratory", *Science* 340(6136):1080–1084, 2013. doi:10.1126/science.1235989 (PMID 23723233, verified 2026-11-14) |
| Collection period | MSL cruise to Mars, December 2011 to July 2012 |
| Units | mSv/day dose equivalent (1.84 mSv/day, galactic cosmic rays, inside the spacecraft) |
| Licence | Published scientific result; used as a single cited number |
| Processing | Used as a constant for a hypothetical Mars-cruise estimate (category C) and as the simulator's background rate |
| Limitations | One spacecraft's shielding during solar maximum conditions of 2011–2012; excludes solar particle events; never presented as a crew dose measurement |
| Integration status | **In code** (`app/space/intel.py`, `app/simulator/radiation.py`) |

## Generated data

### D8. ASTRA-MED crew physiology stream (simulated)

| Field | Value |
| --- | --- |
| Generator | `backend/app/simulator` (seeded; `ASTRA_SIMULATOR_SEED`, default 2026) |
| Content | Four fictional crew members: heart rate, SpO₂, blood pressure, temperature, respiratory rate, synthetic ECG (125 Hz), HRV, sleep, activity, simulated dose; documented test scenarios (desaturation, tachycardia, …) injected on request |
| Units | bpm, %, mmHg, °C, breaths/min, mV, ms, mSv |
| Storage | `vital_samples` (one row per crew member every 5 s), plus sleep and dose tables; every row carries `data_source = "simulated"` |
| Limitations | Physiology is a parametric model, not fitted to real astronaut data; scenarios are software test patterns, not medical events |
| Licence | Part of this repository |

### D9. AI training and evaluation dataset (simulated)

| Field | Value |
| --- | --- |
| Generator | `backend/app/ai/datasets/synthetic.py`; configuration in `backend/app/ai/experiments/config.py` |
| Headline dataset | Fingerprint `eabfda075aa4`: 138,240 five-minute windows, 4 crew, 120 days, seed 7; 327 injected events (255 sudden, 72 gradual, 148 subtle); 3 % missing, 112 artefact spikes |
| Splits | Chronological, day-aligned: train 60 % (to 2026-03-17), validation 20 % (to 2026-04-10), test 20 % (to 2026-05-04) |
| Replication datasets | Seeds 11 and 23 (same generator, different histories) for the [replication study](../backend/experiments/results/seed-study.md) |
| Limitations | Events, physiology and labels share one design; results describe recovery of the simulator's own patterns, not real-world accuracy |

### D10. Benchmark load-test rows (synthetic)

Generated only in a separate `astra_med_bench` database to give PostgreSQL a realistic volume
(about 2.0 million rows: 29 days × 4 crew × one row per 5 s). Values are a smooth daily pattern plus
noise, not simulator output; they are never shown as crew data and the script refuses any database
whose name does not contain `astra_med_bench`.
